## T-lines (parts) left manual, and why
- **T39:** opening the files in Excel or Numbers (a person and a spreadsheet program; the tests check
  the BOM, separators and decimals that make them read right); finishing the import of the two
  files (the tests stop once the columns are matched, which is what the line asks; the import
  itself is the import area's).
- **T44:** checking the Portuguese wording reads well (the tests check the section names only).
- **T56:** that an invite and an emailed quote still **arrive** (a real inbox); "Send a test" on a
  real device with notifications on (headless Chromium has no push service, so the test gives it a
  stand-in subscription); raising `daily_email_cap` after upgrading Brevo (an owner step).
- **T57:** that the client gets one email and its link works (a real inbox: the test makes a link
  only, so no email leaves the test project); inviting a new address from two tabs at once (it
  emails a real address through Brevo; the send-invite claim is covered by
  `supabase/tests/no_double_sends.sql`).
- **T88:** a booking clash on the Crew tab and short gear on Equipment standing out (the rows'
  look; the gigs and inventory areas test the clash and shortage themselves).
- **T89:** Find crew → ⋯ → Report on a person (needs a findable crew profile in another company,
  the marketplace area).
- **T90:** "Fill gig from quote" and "Open gig" with a linked gig, and "Cancel quote" on a sent
  quote (the tests check a draft quote's menu).
- **T91:** "buttons are easy to hit" and "one green button per screen" beyond what the tests
  check (key buttons on screen, ⋯ size): a person's eye.
- **T92:** an invoice (it opens as a dialog from Invoices, and needs an issued invoice, the quotes
  area's); "text is readable, nothing cramped": a person's eye.
- **T125:** until test_support is installed, the "Expired" row (it can only be made by the nightly
  job); the test then runs by itself.
- **T132:** scanning the printed paper with a phone camera and printing / Save as PDF (a printer and
  a camera; the test reads the same QR from the page).

## Bugs found
- None new. The client's quote page (`/q/…`) fails the accessibility check on colour contrast at
  320 px too: that is the known bug **#146** (documented by its own `test.fail()` in
  `quotes.spec.js`), so the T92 sweep checks that page's width but not axe.

## Notes for whoever runs it
- **T56** uses up the `worker` account's five test notifications for an hour: running the file again
  with the **same** `E2E_RUN` tag within the hour fails that test. CI uses a new tag per run.
- **T89** gives the `tech` account two-step sign-in (an authenticator factor, `totpCode`) to post a
  job, and removes the factor at the end so the sweep (password sign-in) can still delete it. If a
  run is killed in between, that account may be left for a manual sweep.
- **T163** deletes the `extra2` account itself; the sweep then finds nothing to delete for it.
