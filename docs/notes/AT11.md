## T-lines (parts) left manual, and why
- **T173:** subscribing in a phone's calendar app (Apple, Google) and seeing the events there needs a
  real device; the test reads the same feed the phone would.
- **T170, T171:** the wording of the notifications in Portuguese and the push notification on a
  phone; the tests check the English bell.
- **T176:** "the totals look right" is checked for weight; the volume figures are not compared by hand.
- **T184:** reading the chart itself (that it looks right) needs a person; the test checks it's there.
- **T169:** the gig's status is changed through the database API (the same update the gig's edit form
  makes); the status picker itself is covered by the gigs tests.

## Bugs found
- **#222 (should fix):** Reports → Vehicle use can't load a period that hasn't started yet: the
  comparison period comes out empty and `vehicle_use` refuses it with "Bad period", so the whole view
  says it couldn't be loaded. Documented by `vehicle use for a period that hasn't started yet loads`
  with `test.fail()`; the T184 tests use a period that includes today.
