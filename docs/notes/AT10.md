# AT10: Automated tests, field tools

## Changelog
### Added
- **Automated tests for the field tools (AT10).** 26 signed-in browser tests in
  `e2e/auth/fieldtools.spec.js` (input list, stage plot, patch, DMX patch, light plot, sound system
  calculator, rehearsal notes, DMX calculator, MVR and GDTF) and `e2e/auth/fieldtools-power.spec.js`
  (power plan, cables, inrush, power report, rigging, line arrays), tag `@fieldtools`, now check
  T26–T30, T46, T48, T97, T99, T101, T106, T107 and T109–T119 on the test project every night. The
  smoke test (the input list, from "Add a tool" to the organisation unticking it) runs on every pull
  request. Calculators are checked against the exact figures for known inputs, worked out by hand in
  the tests' comments; drawings are dragged with the mouse and checked in the database.

Rigging, power and cable results are labelled as aids for a competent person: the tests check the
power plan's "Estimates to plan with, for a qualified electrician to check…", the rigging tool's "An
aid, not a sign-off…" and the line arrays' "…an aid that a competent rigger must check" on each
screen they use. Truss and hoist figures come only from data already in the repo (the Chainmaster
D8+ 500 kg preset from its data sheet, the L-Acoustics K2 and K2-BUMP from the owner's manual); no
truss data was added or changed.

## T-lines (parts) left manual, and why
- **Printing on paper (T26–T30, T46, T113):** the tests open each print view and check what it
  shows; pressing Print and the paper itself need a person and a printer.
- **Phones (T27, T46, T48):** the tests use a desktop browser (and the network switched off for
  "offline"); how it feels on a real phone, airplane mode on a real device and the screen sizes stay
  manual.
- **T46:** the camera sync and LTC timecode (need a camera and an audio signal), a photo with a note
  (camera), a dictated note (microphone); "within a frame or two" between two real phones (the test
  checks the two clocks agree within the time between two readings plus 3 frames, in one computer).
- **T48:** matching a real fixture's switch label is the owner's judgement.
- **T99:** an MVR exported from Vectorworks, grandMA3 or Capture for a real rig, and opening AVX's
  export in Vectorworks: the test uses a small made-up file in the Vectorworks style.
- **T101:** a real manufacturer's GDTF file from GDTF Share: the test uses a small made-up one.
- **T27–T30, T97, T106, T114, T117–T119 questions to the owner** ("is the library missing
  anything", "are the names and columns what your crew expects", "do the figures match what your
  system tech would set"): the owner's judgement.
- **T113:** the label print itself (sizes on real label stock); T130 (inventory area) checks the power
  labels' sizes and bands in more detail.

## Bugs found
- **#229 (should fix):** the patch's stage boxes and the light plot's positions are saved as one
  object per change, without waiting for the save before; two changes a moment apart can be saved out
  of order, so the second is lost while the screen still shows it (seen on the test project for the
  stage boxes and a bar's phase; the same kind of save is used by the sound system calculator and the
  line arrays, where quick splay edits lost one too). The tests wait for each save before the next
  change, as a person at a normal pace would, so they don't depend on it.
- No other app bugs found. One T-line wording differs from what the app (and the beam maths) does:
  see *Needs your decision*.

## Needs your decision
- **T115 wording:** "a point in the middle of a three-point line and a heavy load on an overhang: the
  far point says it would be pulled up". With the overhang past the last point, a continuous truss
  over three points lifts the *middle* point (the test: −1295.5 kg at 1.5 m), while the far end point
  is pressed down (270.3 kg). The test checks what the app shows, which is what the beam maths gives.
  If you meant a different set-up, say which and the test can follow it.
